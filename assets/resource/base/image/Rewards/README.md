# 奖励模板与堆叠数量

御魂与觉醒的“御魂奖励掉落统计”/“觉醒奖励掉落统计”和对应玩法的网络上报默认都关闭，两个开关相互独立。图标用 MaaFramework TemplateMatch 识别物品，只有右下角的数量使用局部 OCR；不会用 OCR 猜物品名称。统计先暂存，成功结算返回玩法页后才累计。同一场反复点击结算不会重复累计。

## 手动添加物品

- `Common/`：两个任务都使用，例如金币。
- `Mitama/`：御魂掉落。
- `Awakening/`：觉醒掉落。
- 可以继续分子目录；PNG 会递归自动发现，不需要改 Python。添加图片后重新加载资源或重启任务，使框架载入新模板。

文件名就是统计名称，例如 `招财猫·六星.png`。同物品的亮暗或样式变体用 `招财猫·六星@亮.png`、`招财猫·六星@暗.png`；`@` 之前的名字相同就合并。同一位置的变体只计一次，不同位置的同物品会累加。不同星级、等级请使用不同名称。

模板请从无损、短边720像素的结算截图裁剪。推荐完整奖励方格：物品识别会返回这个方格的位置，然后在其右下角读数量。**模板中的数量文字、动态光效、UP标记等变化部分请涂成纯绿色 RGB(0,255,0)**；TemplateMatch 默认启用 green_mask，避免“单个”和“堆叠12个”因数字变化无法匹配。不要把其它物品或旁边格子的内容裁进模板。

开启统计后，任务每场保留最近一张原始结算图，方便后续裁剪：

- `debug/rewards/Mitama-last-settlement.png`
- `debug/rewards/Awakening-last-settlement.png`

当前模板来自已授权各1场采样；覆盖本次出现的物品，不代表完整掉落表。御魂花札名称由用户的物品详情截图确认。没有模板的物品不会被猜测为其它奖励。

## 可选 catalog.json

直接放 PNG 就能发现；同目录 `catalog.json` 可覆盖阈值、搜索区域、堆叠数量区域。已有清单不会屏蔽后来新增的同名 `@变体` 图片。仅调整数量等配置时可以不写 `templates`。

```json
{
  "御魂花札": {
    "threshold": 0.88,
    "quantity_mode": "optional",
    "quantity_roi": [50, 69, 42, 24]
  }
}
```

`quantity_roi` 是相对**模板匹配框左上角**的 `[dx,dy,width,height]`，不是屏幕绝对坐标，也不是四项加减偏移。以上数值仅适用于随项目提供的裁剪模板；新模板应按自己的裁剪范围设置。

| 字段 | 默认和用途 |
| --- | --- |
| `templates` | 可选，指定本目录内的PNG；与自动发现的同名变体合并 |
| `threshold` | 默认0.8，可按截图提高匹配阈值 |
| `roi` | 默认奖励区 `[210,140,900,390]`，可按实际奖励布局调整 |
| `green_mask` | 默认true，忽略纯绿色区域 |
| `quantity_mode` | 默认optional；显式写quantity_roi但省略模式时为required |
| `quantity_roi` | 默认取完整模板方格右下角；只裁图标时应显式设置 |
| `quantity_min_white_pixels` | 默认20，用来区分空白高光和白色数量字形，可按数字样式调整 |

数量模式：

- `single`：一个命中就是一个，不读取数量。仅用于确定永不堆叠的物品。
- `optional`：有数字就读取；OCR成功执行且局部没有足够的白色数字笔画时按1个。OCR调用失败、存在数量笔画但文字无法读清时标记未知。
- `required`：必须读到正整数，例如金币；读不到时标记未知。

数字只接受正整数，兼容全角数字和`×12`等前缀；不会把`1.2`或非数字内容强行转换。`物品名（数量未识别）: 1` 表示一个待核对的图标，**不表示实际数量为1**。

## 本地结果

`debug/rewards/Mitama-latest.json`、`Awakening-latest.json` 保存本场 `drops` 和当前任务累计 `totals`。日志同时输出每场与累计统计。不同任务、关卡的网络记录不会混在同一条累计上报中。失败、漏点及单纯等待不会提交成功奖励。

## 流程参考与验证边界

战斗准备、战斗中等待、结算与异常处理的划分参考 OnmyojiAutoScript `88c3a936246fc95ad1a48feecc0acd71d3f5508a` 的 `tasks/Orochi/script_task.py`、`tasks/EvoZone/script_task.py` 及 `tasks/Component/GeneralBattle/`。本项目使用原生 Pipeline 调度，继续保留已有的“首次选层”和“返回后成功计数”规则；未复制外部源码或图片。

本轮完成御魂与觉醒各1场实机采样，并离线回放真实奖励图；另外用合成堆叠数字验证数量累加。这不等于完整掉落表都已测试。统计与上报均默认关闭；只有用户开启统计才执行匹配和保留结算图。

## 截图时机和选项名称

开启统计后，结算页先等待至少2秒让奖励逐个入场，再调用框架原生稳定等待：图标行连续稳定1秒、最多等待8秒。等待失败不会保存画面或累计；成功后才读取新画面，并再次检查仍在成功结算页、没有失败或覆盖弹窗。

御魂与觉醒的统计、上报及地址选项均有玩法前缀。新配置的统计与上报仍默认关闭。
